# dsh-amphoreus 0.2.1

`0.2.1` 修复了角色会话建立、首次回复和会话管理中的实际交互问题，并提供一次提问、十三席分别回复的全席征询。插件继续兼容 **DeepSeek Harness `0.1.2-alpha.4`**，技能套件由运行时从外部目录读取。

## 安装与升级

```bash
dsh plugin --profile web add dsh-amphoreus@0.2.1
```

也可以使用 `dsh-amphoreus@alpha`。安装或升级后停止当前 DSH Web 进程，再运行 `dsh web`；插件 bundle 在启动时加载，配置热重载不能代替本次重启。

tarball 安装：

```bash
npm pack dsh-amphoreus@0.2.1 --registry https://registry.npmjs.org
dsh plugin --profile web add ./dsh-amphoreus-0.2.1.tgz
```

## 角色对话

- 黄金裔席位的新会话等待工作区初始化与会话归属确认后打开，输入框可以直接使用。没有当前普通工作区时，使用该席的内部工作区。
- 历史上缺少工作区归属的席位会话在打开前补齐关联；从黄金裔入口进入时明确激活对话视图。
- 同一席位进行中的新建请求会合并，快速重复点击加号不会连续创建多个空白会话；一次创建完成后仍可主动新增独立会话。
- 角色卡在首个模型请求被接受前注入。修复了通用 DeepSeek 回答先出现、角色回答随后追加的时序问题，并覆盖取消、拒绝和重启后的重试。
- 已绑定角色的会话采用该席身份，替换宿主两段通用身份声明。工作目录、工具说明和运行上下文继续有效；普通会话使用宿主原提示词。
- 角色参考文件按外部技能目录的绝对路径提供，避免把 `persona.md` 或 `common.md` 当成工作目录中的文件。

## 全席征询

进入“全体会议”，输入问题后点击“全席征询 · 13 席”，同一句输入会分别发送给所有已部署席位，最多三席并行。

会议页逐席读取官方会话日志，并依据完整回复和真实结束状态显示进度。每席仍是独立会话，回复完成后可单独打开继续交流。派发失败会留在对应席卡上，不会伪报为完成。

十三席真实调用复核通过：同题输入 `13/13`，首请求包含角色卡 `13/13`，对应角色首答 `13/13`；通用身份前答 `0/13`，双重可见回复 `0/13`。会议页实际显示 `13/13 已回复 · 本轮结束`。

## 会话管理

- 侧栏每段会话提供归档入口和确认操作。空白会话、已有正文的角色会话与普通目录会话都可以归档。
- 每席默认显示最近五段会话，“展开全部”可查看和管理更早的会话。
- 归档状态同步到黄金裔计数、门户、工作台线程树、派发泳道与移交入口；过时的打开、发送或分支操作会检查宿主归档状态。
- 侧栏归档只作用于选中的会话。未归档子分支继续可见，归档父会话不会递归隐藏它们。
- 画布里的“归档此会话及其分支”保留原有语义，确认后隐藏相应画布分支。归档保留 DSH 原始会话日志。
- 内部席位工作区中的无绑定会话显示在“未绑定角色的对话”组，可以直接打开或归档；已有正文的无绑定会话也会显示。已绑定、已归档和已不存在的会话不会重复进入此组。

DSH 的启动导航可能在最近工作区准备一个新的空白草稿。这个草稿现在有可见的管理入口。仅因会话位于某个席位目录，插件不会自动给它绑定角色或注入技能；角色身份仍以实际席位绑定为准。

## 使用边界

- 兼容范围仍为 DSH `0.1.2-alpha.4`。
- 会议的跨席汇总保存在当前页面内存中。刷新、关闭总览或离开承载视图会结束尚未派出的调度；已被 DSH 接受的独立会话继续完成各自的回复。
- 本轮会议中已收到的文本会保留。归档对应会话后，席卡显示“会话已归档”，不再提供打开入口。
- 外部技能卡可能要求开场、回执或多段输出，因此会议征询不保证每席严格只回复一句话。
- 原生启动准备的新空白草稿可直接管理；归档操作不物理删除会话日志。
- 游戏图像与技能正文继续由外部素材和技能套件提供，不纳入 npm 发布包。
